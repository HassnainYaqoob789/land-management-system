# End-to-End Audit and Regression Test — 31 Oct 2026

**Application:** Mari Energies Land Management System
**Databases:**
- `lms_iam_test`: API and UI tests, served on port 3041 from the `.next-test` build.
- `lms_test`: database suite, rebuilt from scratch.
- `lms_dev`: the user's database, migrated to 0059.

The user's server on port 3040 was not touched.

**Method:**
1. Four parallel audits, each tracing page → API → SQL/DB function and checking with read-only SQL:
   - land operations
   - finance
   - master data, reports and other modules
   - identity, roles, menus and permissions
2. Fixes for the confirmed high-impact defects.
3. Regression run of every automated suite, plus a browser walk-through of the new land-request flow.

## 2. Issues found and what happened to them

### Fixed

| # | Severity | Issue | Fix |
|---|---|---|---|
| F1 | Critical | Vouchers on a case could exceed its award. 120,000 was raised against a 50,000 award, and 40,000 of it was released. | `api.request_payment` caps the vouchers on a case at the payable award, counting every unreversed voucher, with the case row locked (0059). |
| F2 | High | A deceased landowner could be paid. | Refused when the voucher is requested, verified or released (0059). |
| F3 | High | Typing a payee name instead of choosing the owner skipped the policy WHT rate and every landowner hold. | A case or lease voucher must name a landowner (DB). On the form, the payee becomes required when a case is chosen. |
| F4 | High | A held lease did not hold its vouchers. | `lms.hold_for` now includes the lease hold (0059). |
| F5 | High | A court stay on a parcel blocked only lease-line cases. | Crop, tree, misc and DBPFC lines on the stayed parcel are now held too (0059). |
| F6 | High | A stay order could not be lifted from the UI: the API needs the court order and the form had no field for it. | Added a "Court order lifting the stay" field, shown when the stay would end. |
| F7 | High | Anyone with `leases:update` could terminate an approved lease and free its parcels. | Termination needs the Manager Land (HO) position and a date on or after the start. |
| F8 | High | Dashboard KPIs returned lessor names and rents, voucher codes and amounts to roles without those registers (e.g. admin, viewer). | Samples are gated by `landowners`/`payments`/`surveys:read`, lease alerts by `leases:read`, and rent by `payments:read`. |
| F9 | Medium-High | Reversed cheques still counted as paid in the landowner summary, project and province figures. The Cheques tab could not tell a cheque was reversed. | Reversals are excluded in `v_landowner_summary`, `v_project_land_status` and `v_province_summary`. `v_payment_release.reversed_at` added. A receipt on a reversed cheque is refused (0059). |
| F10 | Medium-High | The executive dashboard province chart was built from project rows, so it dropped unlinked parcels and double-counted shared ones (SND 165.5 ac shown vs 233.75 real). | Uses the register-based `provincial_breakdown`. |
| F11 | Medium | Owner names and shares were visible to anyone who could read parcels, including the Exploration Planner, reviewers and viewer. | Owner data needs `landowners:read`, and the Shares button is shown only then. |
| F12 | Medium | A CNIC lookup in the person statement revealed whose CNIC it is without `pii:read`. | Now needs `pii:read`; lookup by landowner code is unchanged. |
| F13 | Medium | Other users' draft land requests showed in the Calendar. A draft's id answered 403 (leaking that it exists). | Drafts are filtered from the Calendar, and someone else's draft answers 404. |
| F14 | Medium | Punjab/KPK land requests could never pass tiers 3 and 4: no one held those positions there. | Added `regmgrpnj` and `landaffpnj` accounts (PNJ + KPK). |
| F15 | Medium | "Mark parcels" set Under Acquisition for Lease and DBPFC hand-overs too. | Only an Acquisition hand-over marks parcels. |
| F16 | Low-Medium | Old tier decisions stayed on a request after it was returned and resubmitted. This blocked people in the new round and showed stale "APPROVED". | Resubmitting clears all three tiers (route + `tg_land_request_tier`, 0059). |
| F17 | Medium | A case with no landowners could be fully approved. | `wf_guard_cases` requires owners before Field / HO approval (0059). |
| F18 | Medium | The Owner-shares dialog offered "Save" for parcels that already had owners, and it always failed (409). | Read-only for registered owners, with a pointer to Mutation & Succession. |
| F19 | Low-Medium | Project dashboard: "active leases" included expired ones, and case and lease counts were capped by page size. | Expired leases are subtracted, and totals come from `page.total`. |
| F20 | Low | "Record receipt" was shown to `payments:create` users, but the API refuses them. | Shown only to verify / release holders. |
| F21 | Low | Survey register and Projects were missing from the menu for the planner and reviewer roles, which need them. | `requests:read` added to their menu entries. |
| F22 | Missing | An approved land request could not be turned into an acquisition. | **Create acquisition** opens a form pre-filled with the project, area and parcels inside. The request and the acquisition are linked both ways (0058). |
| F23 | Missing | Hand-over gave no feedback when no parcel was marked. | The message now says why. |
| T1–T3 | Test defects | The roles test aged expired sessions (constraint error). The documents test and server used different stores. My new tests reset fixture passwords in parallel. | Tests corrected; environment documented below. |

### Not fixed: open items, by priority

These need a business decision or are larger pieces of work.

| # | Severity | Item | Recommendation |
|---|---|---|---|
| O1 | **High (config)** | `/api/auth/demo-accounts` hands every demo password, admin included, to anyone who can reach the server. The 3040 server runs with demo mode **on** and is bound to the LAN (`0.0.0.0`). | Turn `LMS_DEMO_MODE` off on any server reachable from the LAN, or bind to 127.0.0.1. |
| O2 | High | `api.adjust_case`: any `cases:approve` holder can raise an HO-approved award with no position, limit or second approval. | Restrict to Manager Land (HO) and add a policy cap or a second approver. *Business rule needed.* |
| O3 | High | SoD gap: an approver can edit a case's valuation (or a mutation's heirs) before the terms freeze, then approve it themselves. | Treat a valuation edit in the current round as preparing it. |
| O4 | Medium-High | Allocation does not use the voucher's payee, and the dialog sends no owner. On multi-owner cases payments are "unattributed", and the receipt's settlement block can show a negative "paid before". | Default the allocation to the voucher's landowner, or auto-allocate at release. |
| O5 | Medium | Only `mland` can reverse a cheque, and the releaser cannot reverse their own. With one Manager Land, nobody can reverse. | A second Manager Land, or a `payments:reverse` permission for Finance. |
| O6 | Medium | `budget_status` counts case vouchers twice, so it over-reports commitments. | Mostly removed by F1; finish by excluding case vouchers from "pending". |
| O7 | Medium | SAP outbox: reversals are never sent, and the payload has no gross / WHT breakdown. | Add a `payment.reversed` event and tax fields. |
| O8 | Medium | Payment form cannot link a voucher to a lease or a DBPFC estimate (the API supports it). | Add pickers. |
| O9 | Medium | Required documents and title checks can be unticked after approval. | Lock them past Field Approved. |
| O10 | Medium | Cancel / Stop has no position check (any approver, at any stage before HO approval). | Add step groups for Cancelled / Stopped. |
| O11 | Medium | A lease hold can be lifted by anyone with `leases:update`, including the person who did not place it. | Require a different user and the Legal or Manager Land position. |
| O12 | Medium | Leases and ROWs can be approved with no lessor or parcel. | Add workflow guards. |
| O13 | Medium | Survey import loses the recorded unit and area, and matches a deh by name only. | Store the recorded area and unit; require a unique leaf unit. |
| O14 | Medium | Land requests are not in Approvals & Alerts, and notifications are never created (REQ-39). Reviewers must open Land Requests to find work. | Add a land-request queue and notifications. |
| O15 | Medium | Hand-over → record link exists for Acquisition only. | Same once-only link for Lease, Case and DBPFC. |
| O16 | Low-Medium | Lease rate is computed in the browser (float) and trusted. | Send the annual rent and derive the rate on the server. |
| O17 | Low | Unbounded lists: `/api/projects`, `/api/gis`; the Documents picker is capped at 100. Import reconciliation is not province-filtered. Inbox totals are counted before scope. | Paging, `RecordPicker`, and a province filter. |
| O18 | — | Earlier open items still stand: Urdu/Sindhi receipt, Playwright UI test drift, LAA milestones (REQ-06), WHT override policy, real SSO, maplibre advisory, no UAT, and no git commit of the code. | See CLAUDE.md §9. |

## 5. Overall status

- The core flows work end to end: land request → approvals → hand-over → acquisition, and case → voucher → verify → release → receipt.
- The audit's most serious money and permission defects are fixed and covered by tests.
- The application is **still not releasable**. The reasons:
  - O1 (demo passwords on the LAN) needs a configuration change now.
  - O2–O5 are business-rule and SoD gaps in finance and case approval that need decisions.
  - The release blockers from 29 Oct (LAA milestones, WHT override policy, real SSO, UAT, performance) are unchanged.
